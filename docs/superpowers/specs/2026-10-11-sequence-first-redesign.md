# Sequence-first website redesign

The user approved a Google-like sequence-first entry, mode selector above the input, and a bottom Advanced entry. Their latest correction makes Advanced expand inline and scroll into view, like Go results. The supplied hand sketch and subsequent corrections define the scope. Functional elements combine existing annotations and predictions; RNAfold initially analyzes the generated arRNA sequence. The existing website is recoverable from GitHub branch `backup/pre-homepage-redesign-20261011`, commit `e7ca2fad323360732165803ed59e6b4d254311d2`.

## User experience

- Visual language: warm off-white canvas, white cards, graphite primary controls and restrained pale-gold selection/focus details. LEAPER uses a readable Cormorant Garamond italic wordmark; body text and sequence letters remain Arial. Evidence categories and structural/probability legends retain distinct semantic colors.
- Sequence input, sequence selection, normal/exon results and Advanced share one centered 1280 px maximum content width, shrinking together to the available viewport width. Their outer edges align; existing internal spacing and base font sizes remain unchanged.
- Replace the landing-page module cards with the actual design input. Normal / Exon skipping is a compact segmented control above its left edge. Paste one sequence, inspect it, then run Go. Preserve help, method, language, and citation access.
- Normal: click an A in the sequence to select it. No implied reading frame for arbitrary pasted RNA. Coding context follows the input source or saved link; Advanced exposes ADAR choices but no manual coding-context switch.
- Exon skipping: paste one pre-mRNA context and define an internal target exon with two boundaries directly in the sequence window. Upstream/downstream input portions become user-defined introns. Also provide precise numeric boundary controls. No auto-inferred intron claim.
- Sequence display uses Arial bases without individual keycap boxes, position numbers, continuous region highlights and source details in the sequence viewer. Mouse, keyboard and touch interactions must work. Show source and evidence status for each feature.
- Exon selection uses a continuous pale-gold background. User-defined intron/exon regions remain in the annotation details but do not paint the whole sequence green. Functional evidence uses its categorical background outside the selection and a thin underline inside it; reference, predicted and other user annotations have a fixed display priority independent of response order.
- Keep the homepage sequence picker minimal: one selection prompt and a single length indicator. Omit the decorative subtitle and repeated sequence headings. Keyboard and coordinate guidance remain available to assistive technology; dynamic exon-boundary feedback stays visible. Preserve the original 14 px base letters; the user's request concerns excessive explanatory text, not enlarging the sequence.
- Advanced: the bottom-centered trigger expands a rounded white card below itself in normal page flow, then focuses and scrolls to it. The page stays interactive and scrolls as one document. Close/Escape returns focus to the trigger; reopening preserves settings and the selected tab. Honor reduced-motion preferences. External draft links reveal the appropriate tab and scroll to the open card again; internal tab changes do not move the page. Only Design and Reference remain. RNAfold model settings are grouped with design settings; the separate RNAfold and Features tabs, the Features panel and the homepage feature link were removed at the user's request. Automatic annotation and the main sequence highlights remain active.
- Coverage is selected visually in Advanced: drag either edge of a pale-gold window around a fixed A0 marker, use arrow keys for 1 nt adjustments, or enter precise relative bounds. Show absolute coverage and length, clamp interactive edits to the sequence and keep A0 inside. The overview carries reference, predicted and user annotation color tracks from the same feature data as the main sequence; the selection does not hide those colors. Reset restores the existing −75/+75 defaults; short input only clips the initial visualization without silently changing request settings. Existing NP checks remain authoritative. Bulge customization reuses validated structural operations. Experimental refinement and its navigation/help entries have been retired at the user's request.
- Advanced settings are drafts. The Apply action in Design validates and commits a new result, closes Advanced, then focuses and scrolls to the result. Existing results and their exports stay unchanged while editing or after a failed request. Any new edit, including incomplete numeric text, invalidates an older pending Apply. Custom structure outputs are published only after Apply succeeds; their export uses the applied snapshot.
- Each successful custom Apply adds and selects a new numbered Custom arRNA card in the existing candidate group. Custom cards use the same RNAfold thumbnail, pairing diagram, sequence and Copy/Download controls as the normal candidates. Earlier custom cards remain available for comparison; selecting one restores its saved structures for editing, and another custom Apply creates a new card. Advanced contains no independent custom sequence/export box, long coordinate explanation or Design notes disclosure; validation errors remain visible. Unified JSON keeps each custom design's source result and structure snapshot; CSV identifies each custom row's actual builder.
- Every homepage Go explicitly restores recommended design settings and submits a fresh recommended snapshot, even after custom settings were applied or restored from a link. Only Advanced Apply submits the current draft. Go clears all custom cards and structures and restores the default candidate and linear folding model when its result succeeds; failed or stale requests cannot replace the previous result. Input sequence, target/exon boundaries and reference provenance remain intact. Coding context is retained from the current input (ordinary paste: false; coding example/reference: true; saved links preserve their declared context).
- Recommended defaults come from one shared preset: centered A0 −75…+75 coverage (151 nt including A0), ADAR1, optional +4 off, linear RNAfold, exon arRNA length 151 nt, and covered-ESE evaluation off with no extra positions. New sequence input, a mode change, an example or a newly loaded reference starts with this preset. Changing the target A recenters the window without changing sequence context. Explicit saved-link settings still restore; closing/reopening Advanced preserves drafts. Restore defaults clears custom design drafts and restores the preset, while preserving the input, target, coding/reference context and applied result until Apply succeeds. Sequence-end clipping remains visible and never moves the selected A.
- Initial results retain candidate selection, pairing overview, full sequence and copy/download; the extra detail disclosures have been removed. Each candidate automatically shows an RNAfold thumbnail. Only the explicit enlarge button at the top right of a thumbnail opens an enlarged, dismissible structure viewer; the image, metrics and surrounding preview remain noninteractive with a normal cursor; no separate large structure remains below the result. Header selection and thumbnail zoom use separate accessible buttons. Candidate names and lengths stay on one line, with fewer card columns on narrower containers. RNAfold receives the current applied candidate or applied custom arRNA. Design contains the draft RNAfold model control; model changes take effect on Apply. Shared normalized-sequence/model caching prevents duplicate card/detail requests, with two concurrent requests, explicit retry after failure and stale-response isolation. Exon candidates use the same structure presentation.
- Footer citation area: LEAPER 3.0, Nature Protocols, and NAR. Reuse verified existing publication details; explicitly pending entries for unavailable citations. Do not invent DOI or journal acceptance.

## Scientific scope

- The normal pairing overview uses a centered compact duplex with closely spaced strands and fine pairing links. Unpaired target spans form rounded gold loops with narrow openings; these spans are compressed on screen, so the accessible description and help identify the diagram as not to scale. A-site dots retain their source coordinates and follow sequence order around each loop. The target/guide pair and deletion counts remain prominent; detailed positions are available on hover. Small containers scroll the schematic horizontally instead of shrinking its labels excessively.
- Advanced Custom structures shares the same renderer and styling. Target deletions form upper gold loops, arRNA insertions form lower green loops at the supplied before-base boundary, and internal mismatches bend both strands outward in purple. Edits update the draft preview immediately; the existing Apply step still commits results. Invalid out-of-window display regions do not distort the diagram, while editor validation remains visible.

- Preserve fixed NatureProtocol rules and all current design-engine behavior. This redesign does not approve changing automatic recommendation scores or measured experimental data.
- Functional annotation: allow user-defined regions; retrieve reference features only from a supplied exact accession and a verified unambiguous sequence mapping. Failed/ambiguous mapping gives an honest message, never false reference features. Scan the existing five published ESEfinder matrices as a scoped set of predicted SR-protein motifs; describe this coverage explicitly rather than claiming a universal RBP screen. Include motifs without A in this annotation-only scan; leave exon design candidate behavior unchanged.
- Reference features and predictions coexist. Reference annotation is not equivalent to experimentally demonstrated activity in the current cell type.
- RNA structure: use real ViennaRNA/RNAfold minimum-free-energy and partition-function calculations. Display secondary structure and per-base unpaired probabilities plus their mean; MFE is supplemental. No editing-efficiency prediction or fabricated looseness score. Linear arRNA model by default, selectable circular model explicitly labeled; neither adds construct/linker sequences.
- Bound requests: annotation sequence <=20,000 nt; structure 5–1001 nt; invalid input and unavailable engines return explicit errors. Keep sequence text out of URLs and subprocess command arguments.

## Shared interfaces

All feature coordinates are 1-based inclusive, relative to the submitted normalized sequence. RNAfold sequence normalization uses U; annotation/design may normalize T/U internally without changing coordinates.

`POST /api/v1/analysis/annotations`: `{sequence, transcript_accession?: string, regions?: [{start,end,kind,label?}]}` -> `{sequence, features: [{id,start,end,kind,label,evidence,source,description,source_url?,score?,protein?}], warnings: string[], prediction_method: string, reference_accession?: string|null}`. Evidence is `reference | predicted | user`.

`POST /api/v1/analysis/rnafold`: `{sequence, topology?: 'linear'|'circular', temperature?: number}` -> `{sequence, structure, mfe, ensemble_free_energy, ensemble_diversity, unpaired_probabilities: number[], mean_unpaired_probability, mfe_unpaired_fraction, pairs: [{i,j,probability}], coordinates: [{x,y}], engine, version, temperature, topology}`. Pair indices are 1-based; coordinate/probability arrays follow input order.

Frontend shared types in `frontend/src/lib/sequenceAnalysis.ts`. UI primitives `SequenceExplorer` and `AdvancedSheet` are independent of the design API. Analysis panels own request/error/stale-state handling. Main workspace owns sequence, boundaries, target, selected guide, and design results.
